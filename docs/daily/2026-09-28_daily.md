# Tagesbericht Entwicklung — 2026-09-28

## Zusammenfassung

Items mit Kindern zeigen jetzt im Baum, auf Kanban-Karten und im Graphen einen
Fortschrittskreis. Backlogs, deren Kopf die deutsche Format-Kennung
„Backlog-Format Version 1“ trägt, werden als strukturiertes Format erkannt.
Die Änderungen stammen aus einer früheren Session und wurden heute
committet. Außerdem spricht die API Items jetzt nur noch über Quelle und ID
an, mit einem Versions-Token gegen verlorene Änderungen; einfache Checklisten
ohne IDs werden nicht mehr unterstützt. Der Server erzwingt die Parent-Regeln
des Backlog-Formats. Im Baum lassen sich alle Epics bzw. Stories auf einmal
auf- und zuklappen, und der Fortschrittskreis steht direkt hinter dem Titel.
Danach wurde EPIC-001 fertig umgesetzt: Agenten können Backlogs vollständig
über die API pflegen (Überblick, Anlegen, alle Felder ändern, Notizen und
Specs, Löschen), der Port ist nur noch lokal erreichbar. Löschen läuft
inzwischen über einen Papierkorb, aus dem Items samt Kindern
wiederhergestellt oder endgültig gelöscht werden. Zum Schluss wurde die
Backlog-Pflege in die Oberfläche gebracht: Bearbeiten-Modus, Anlegen,
Löschen mit Papierkorb-Ansicht sowie Notizen und Specs schreiben und ändern.
Zuletzt liefert der Lean Index zusätzlich die Area je Item, damit Agenten die
Relevanz eines Items vor dem Einzelabruf einschätzen können. Danach wurden
Status, Priorität, Bereich, Pflicht für Parent und Abhängigkeiten im
Detail-Panel wieder direkt änderbar; Titel, Texte und Parent bleiben im
Bearbeiten-Modus.
