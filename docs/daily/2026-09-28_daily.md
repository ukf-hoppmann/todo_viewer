# Tagesbericht Entwicklung — 2026-09-28

## Zusammenfassung

Items mit Kindern zeigen jetzt im Baum, auf Kanban-Karten und im Graphen einen
Fortschrittskreis. Backlogs, deren Kopf die deutsche Format-Kennung
„Backlog-Format Version 1“ trägt, werden als strukturiertes Format erkannt.
Die Änderungen stammen aus einer früheren Session und wurden heute
committet. Außerdem spricht die API Items jetzt nur noch über Quelle und ID
an, mit einem Versions-Token gegen verlorene Änderungen; einfache Checklisten
ohne IDs werden nicht mehr unterstützt.

## Features

### Neu

| Fähigkeit | Praktische Wirkung | Nachweis |
|---|---|---|
| Einzelabruf per ID | `GET /api/v2/items/{source_id}/{item_id}` liefert ein Item, egal ob aktiv oder archiviert | bd27bfa, [STORY-003](../todo/items/STORY-003/) |
| Fortschrittskreis | Items mit Kindern zeigen zwischen Prioritäts-Punkt und Typ-Badge ein Tortendiagramm „erledigt/gesamt“ über alle Nachkommen; auch auf Kanban-Karten und Graph-Knoten | 21f03c0 |

### Geändert

| Fähigkeit | Praktische Wirkung | Nachweis |
|---|---|---|
| Bearbeiten per ID und Version | `PATCH /api/v2/items/{source_id}/{item_id}` mit Pflicht-`version` ersetzt `POST /items/edit`; wurde das Item inzwischen geändert, antwortet der Server mit 409 `version_conflict`. Änderungen an anderen Einträgen derselben Datei blockieren nicht mehr | bd27bfa, [STORY-003](../todo/items/STORY-003/) |
| API-Vertrag der Items | `source_id`, `id`, `archived`, `version` statt `ref` (mit Zeile und Ablageort) und `format`; `key` bleibt beim Archivieren gleich. Detailpanel zeigt keine Zeilennummer mehr | bd27bfa |

### Entfernt, abgelehnt oder zurückgestellt
