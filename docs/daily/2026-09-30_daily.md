# Tagesbericht Entwicklung — 2026-09-30

## Zusammenfassung

Die API kann jetzt den Typ eines Items ändern. Weil das ID-Präfix der Typ ist, bekommt das Item dabei die nächste freie ID des neuen Typs, und alle Verweise im Backlog ziehen mit. Die Antwort nennt zusätzlich die alte ID und einen Hinweis, dass Verweise außerhalb des Backlogs (Techdocs, Tagesberichte, Code, Commits) nicht angepasst wurden. Das Feature ist als `v0.1.1` und mit dem geänderten Antwortformat als `v0.2.0` veröffentlicht, aber noch nicht im laufenden Container: dafür fehlt `./todo.sh update`. Eine Oberfläche dafür gibt es noch nicht; sie ist als `STORY-018` angelegt.

## Funktionen

### Neu

| Fähigkeit | Praktische Wirkung | Nachweis |
|---|---|---|
| Typ eines Items ändern: `POST /api/v2/items/{source}/{id}/retype` mit `{version, type}` | Das Item erhält die nächste freie ID des Zieltyps (Epic, Story, Task). Nachgezogen werden `Parent` und `Dependencies` aller Items (auch Archiv und Papierkorb), ID-Erwähnungen in Titel, Summary, Goal, Completion criteria und Resolution, Inhalt und Dateinamen der Notes und Specs sowie der Ordner `items/<ID>/`. Die Antwort ist `{item, old_id, notices}`: das Item unter der neuen ID, die alte ID und der Hinweis `external_references_may_remain` (stabiler Code für die UI, englischer Text für Agenten, die danach suchen können). `PATCH` lehnt `type` weiter ab. Die Parent-Regeln werden vorher geprüft (z. B. ein Epic mit Parent wird abgelehnt), Regelverstöße, die das Item schon unter der alten ID hatte, blockieren nicht. | 8674de9, [TASK-002](../todo/items/STORY-007/STORY-007_notes.md) |

## Entscheidungen und Alternativen

| Entscheidung | Grund und Alternativen | Nachweis |
|---|---|---|
| Typwechsel als eigener Endpunkt mit neuer ID statt als `PATCH`-Feld | Die Adresse des Items ändert sich, das passt nicht zu einer Feldänderung. Die ID zu behalten hätte den Typ und das Präfix auseinanderlaufen lassen. | 8674de9 |
| Hinweis auf Verweise außerhalb des Backlogs als `notices` in der Antwort | Der Server kann Techdocs, Berichte und Code nicht anpassen. Ein Code mit englischem Text lässt die UI übersetzen und Agenten auf Anfrage nach der alten ID suchen. Eine eigene Abfrage oder ein Header wurden verworfen, weil die Antwort selbst den Hinweis trägt. | siehe Merge „Typwechsel: Antwort mit alter ID“ |
