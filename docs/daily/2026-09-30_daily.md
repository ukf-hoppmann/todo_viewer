# Tagesbericht Entwicklung — 2026-09-30

## Zusammenfassung

Die API kann jetzt den Typ eines Items ändern. Weil das ID-Präfix der Typ ist, bekommt das Item dabei die nächste freie ID des neuen Typs, und alle Verweise im Backlog ziehen mit. Die Antwort nennt zusätzlich die alte ID und einen Hinweis, dass Verweise außerhalb des Backlogs (Techdocs, Tagesberichte, Code, Commits) nicht angepasst wurden. Im Detail-Panel gibt es dafür den Button „🔁 Typ ändern“: Nach dem Wechsel ist das Item unter der neuen ID ausgewählt, und ein Hinweis nennt alte und neue ID sowie die möglichen Verweise außerhalb des Backlogs. Veröffentlicht sind `v0.1.1` (Endpunkt), `v0.2.0` (geändertes Antwortformat) und `v0.2.1` (UI), aber noch nicht im laufenden Container: dafür fehlt `./todo.sh update`. Zwei Backend-Tests, die vom echten Datum abhingen, laufen jetzt mit festem Datum und sind grün. `TASK-002`, `STORY-007` und `EPIC-001` sind bestätigt und abgeschlossen; `STORY-018` wartet auf Bestätigung. Außerdem sind die Architekturregeln so geöffnet, dass ein Projekt künftig wahlweise in Markdown-Dateien oder in einer zentralen Datenbank gespeichert werden darf; im Code sind dafür das Feld `Source.backend`, ein Routing je Projekt und eine gemeinsame Test-Suite für die Speicher-Ports vorbereitet (noch kein zweites Backend). Die Farbe der Priorität „Normal“ ist Grau statt Violett. Veröffentlicht ist `v0.2.2`. Danach wurde der Dokumentzugriff umgebaut: Notizen und Specs werden intern nur noch über Item-ID und Dokumentnamen angesprochen, die Ordnerstruktur `items/<ID>/` kennt allein der Markdown-Adapter. Nach außen ändert sich dabei nichts außer einmalig der `version` von Items mit Dokumenten; ein Release gab es dafür nicht. Zuletzt kam die zentrale Datenbank dazu: Ein Projekt, das in `config.json` mit `"backend": "database"` eingetragen ist, wird vollständig in SQLite (`configs/todo.db`) gespeichert, samt Archiv, Papierkorb, Notizen und Specs, und funktioniert über dieselbe API. Markdown-Projekte bleiben unverändert, die Datenbankdatei entsteht erst bei Bedarf. Veröffentlicht als `v0.3.0`; im laufenden Container erst nach `./todo.sh update`. Mit `v0.4.0` liegt auch die Projektliste samt UI-Zustand in dieser Datenbank: Datenbank-Projekte lassen sich über `POST /api/v2/sources` anlegen, und eine bestehende Installation übernimmt beim ersten Zugriff ihre Projekte aus `config.json` und `ui_state.json` (Sicherungen `.bak`). Dabei bekommen alle Projekte neue `source_id`s (UUID). Der laufende Container hat noch den alten Stand; die Übernahme passiert erst mit `./todo.sh update`.

## Entscheidungen und Alternativen

| Entscheidung | Grund und Alternativen | Nachweis |
|---|---|---|
| Typwechsel als eigener Endpunkt mit neuer ID statt als `PATCH`-Feld | Die Adresse des Items ändert sich, das passt nicht zu einer Feldänderung. Die ID zu behalten hätte den Typ und das Präfix auseinanderlaufen lassen. | 8674de9 |
| Hinweis auf Verweise außerhalb des Backlogs als `notices` in der Antwort | Der Server kann Techdocs, Berichte und Code nicht anpassen. Ein Code mit englischem Text lässt die UI übersetzen und Agenten auf Anfrage nach der alten ID suchen. Eine eigene Abfrage oder ein Header wurden verworfen, weil die Antwort selbst den Hinweis trägt. | siehe Merge „Typwechsel: Antwort mit alter ID“ |
| Dokumente über Item-ID und Namen statt Pfade, Umbau vor dem Datenbank-Adapter | Der Port war pfadbasiert, weil es nur Markdown gab; eine DB hätte sonst Ordner und Pfade nachbauen müssen. Fremde Pfade (außerhalb `items/<ID>/`) bleiben als Name erhalten; in den konfigurierten Backlogs kommen sie nicht vor (alle 105 Verweise geprüft). | 909e4c8 |
| Speicher-Backend je Projekt wählbar (Markdown oder zentrale Datenbank), DB intern mit UUID und Label | Die Datenbank soll mit UUIDs arbeiten, API und Markdown weiter mit Schlüsseln wie `STORY-019`; ein Typwechsel ändert dann in der DB nur das Label. Verworfen: Datenbank nur als Cache neben Markdown (widerspricht „keine eigene Kopie“) und automatische Spiegelung (Konflikte ohne saubere Lösung); stattdessen Sync nur auf Anforderung mit Vorschau. | f64b4cc |
